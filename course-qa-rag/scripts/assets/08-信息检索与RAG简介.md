# 信息检索与 RAG 简介

## 信息检索在做什么

信息检索（IR）研究的是：给定查询，如何从文档集合中找出最相关的若干篇或若干段落。搜索引擎是最典型的应用。为了快速定位包含某些词的文档，系统通常会建立倒排索引：从词指向包含该词的文档列表，从而不必每次都把整个资料库扫描一遍。

## BM25

BM25 是一种经典的词法相关性打分函数。它在词频的基础上引入了饱和效应（同一词在一篇文档里反复出现，分数不会无限上升），并用文档长度做归一化，同时结合逆文档频率（IDF）来降低“的”“是”这类常用词的权重。BM25 不需要训练大型向量模型，计算轻量，对专有名词和课堂术语往往很有效，因此很适合作为本地检索、尤其是笔记本电脑演示项目的默认方案。

## 向量检索与语义匹配

词法检索依赖字面重合，遇到同义改写时可能漏召回。例如用户问“训练误差很低但上线效果差”，资料里写的是“过拟合”，BM25 不一定能对上。向量检索把查询和文档编码到同一向量空间，用余弦相似度或内积衡量语义接近程度。两类方法可以互补：先用 BM25 保证关键字命中，再辅以向量模型处理同义表达。

## 检索增强生成（RAG）

大语言模型在没有参考资料时可能产生幻觉，把听起来合理但错误的内容当成答案。RAG 的基本流程是：

1. 将文档切成适当大小的片段并建立索引；
2. 根据用户问题检索最相关的片段；
3. 把问题和检索到的上下文一起送给生成模型；
4. 要求模型只依据上下文作答，并标注来源。

切分过长会引入噪音，切分过短会丢失必要上下文，因此分块大小和重叠是两个需要调节的关键超参数。评估 RAG 时，既要看检索是否召回了正确段落，也要看最终答案是否忠实于资料，而不是只看文字是否流畅。如果资料里根本没有答案，一个合格的系统应明确说“根据现有资料无法回答”，而不是编造。
